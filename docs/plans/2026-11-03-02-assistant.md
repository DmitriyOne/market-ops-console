# Plan 2 — Assistant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working assistant in the right panel (desktop) and the Assistant tab (phone): streamed answers with stop, retry, confidence, sources with evidence cards, the deterministic "What the data shows" check, and links that focus the dashboard through the URL.

**Architecture:** The stream lives in `features/ask-question` (`useChatStream`, `useReducer`, ADR 0003/0006). Citation resolving, evidence numbers and dashboard URL params are pure code in `entities/performance`. The answer anatomy, the data check and the conversation log are one widget, `widgets/assistant-panel` (pages-first: no second consumer yet). The desktop/phone frame is `widgets/app-shell`; the phone tab is `features/switch-section`. `pages/dashboard` only composes. Tokens and look come from ADR 0014 and the canvas boards "A · Assistant", "D + A · Design system", "D + A · States".

**Tech Stack:** as Plan 1, plus shadcn `hover-card`, `popover`, `collapsible`, `textarea` (Radix). No new runtime dependencies.

**Spec:** `docs/specs/2026-11-03-market-ops-console-design.md` §6 (URL state), §7 (Assistant), §8 States, §11a. Decisions: ADR 0003, 0006, 0008, 0013, 0014. Rules: `CLAUDE.md`, `.claude/rules/*`. Canvas: https://claude.ai/artifact/3c27zSahAxyZqqCt65eSLN.

**Plan series:** 1 Foundation (done) → design pass (done, 0.3.0) → **2 Assistant (this, 0.4.0)** → 3 Dashboard → 4 Alerts → 5 E2E, deploy, README. ADR 0014 checkpoint: when this plan is done, compare days left with the dashboard D estimate before Plan 3.

## Review Focus

1. **Stop at any moment** (before the first token, mid-answer, right after `done`) → message is `stopped` with its partial text (or `done` if `done` won), no sources or confidence, no console error; the route stops enqueuing. Tests in Tasks 3 and 8.
2. **Stale events after stop / retry / a fast second question** → events of an aborted stream never change another message. Test in Task 3.
3. **Question that is blank, whitespace or longer than 500 characters** → Send disabled with a reason, no request; the server still answers 400 for a direct call. Tests in Tasks 1 and 4.
4. **Citation with an unknown id or a period outside `meta.periods`** → the source button still renders from `label`; the evidence card says "Not in the dataset"; no crash; period falls back to `latestPeriod`. Tests in Tasks 5 and 8.
5. **Long answer streaming while the user has scrolled up** (`summary-long`) → no forced scroll, "↓ New content" appears and jumps down on click; auto-scroll resumes at the bottom; no smooth scrolling under `prefers-reduced-motion`. Test in Task 7.

### Task 3: `useChatStream` — reducer and hook

**Files:**
- Create: `src/features/ask-question/model/chat-reducer.ts`, `src/features/ask-question/model/use-chat-stream.ts`, `src/features/ask-question/index.ts`
- Test: `src/features/ask-question/model/chat-reducer.test.ts`, `src/features/ask-question/model/use-chat-stream.test.tsx`

**Interfaces:**
- Consumes: `streamSse`, `chatEventSchema`, `ParseError`, `AbortedError`, `errorMessageKey`, `API_ROUTES.chat`, `chatStream`/`chatFromFixture` (tests).
- Produces:
  ```ts
  type MessageStatus = 'streaming' | 'done' | 'stopped' | 'error';
  type ChatMessage = {
    id: string; question: string; text: string; status: MessageStatus;
    kind: AnswerKind | null; citations: Citation[]; confidence: Confidence | null;
    error: { message: string } | { key: ErrorMessageKey } | null;
  };
  type ChatAction =
    | { type: 'started'; id: string; question: string }
    | { type: 'token'; id: string; value: string }
    | { type: 'done'; id: string; kind: AnswerKind; citations: Citation[]; confidence: Confidence }
    | { type: 'failed'; id: string; error: ChatMessage['error'] }
    | { type: 'stopped'; id: string };
  chatReducer(state: ChatMessage[], action: ChatAction): ChatMessage[];
  useChatStream(): { messages: ChatMessage[]; isStreaming: boolean;
    ask(question: string): void; stop(): void; retry(id: string): void };
  ```
  Rules: actions for a message whose status is not `streaming` are ignored (stale guard); `done` with `kind: 'error'` → status `error`, `error: { key: 'errors.server' }`; `stopped` keeps `text`, clears nothing else but `citations`/`confidence` stay empty; `ask` is a no-op while streaming or for a blank question; `retry(id)` asks that message's question again as a new message; ids from `crypto.randomUUID()`; unmount aborts the stream.

- [ ] **Step 1: Reducer tests** (table): token appends; `done` sets kind/citations/confidence; `token` after `stopped` is ignored; `done` with kind `error` → status `error`; `failed` keeps partial text.

- [ ] **Step 5: Hook tests** with MSW (`renderHook`): `'streams at-risk to done'`; `'error fixture ends in error with the event message'` (message === fixture `error` text); `'HTTP 500 ends in error with key errors.server'`; `'invalid event ends in error with key errors.invalidData'` (handler sends `{type:'nope'}`); `'stop mid-stream keeps partial text as stopped'` (`delayMs: 20`, stop after the 3rd token, final text === first 3 tokens, `citations` empty); `'stop then ask again: old stream never touches the new message'`; `'retry adds a new message with the same question'`; `'ask while streaming is ignored'`.

### Task 6: "What the data shows" — the deterministic check

**Files:**
- Create: `src/widgets/assistant-panel/model/data-check.ts`
- Test: `src/widgets/assistant-panel/model/data-check.test.ts`

**Interfaces:**
- Consumes: `resolveCitation`, `computeKpis`, `statusFor`, `nonOnTrackMarkets` (Task 5 / Plan 1).
- Produces:
  ```ts
  type CheckRow = { key: string; resolved: ResolvedCitation; kpis: Kpis; status: MarketStatus | null;
    reason: { kind: 'attainment' | 'growth'; value: number } | null };
  type DataCheck = {
    portfolio: Kpis;                       // latest period, 1m, scope {}
    rows: CheckRow[];                      // one per unique (scope, period) among known citations
    notMentioned: Market[];                // market-list rule
    regionGaps: { regionId: string; markets: Market[] }[]; // region rule, empty regions omitted
    expanded: boolean;                     // notMentioned.length > 0 || regionGaps.length > 0
  };
  buildDataCheck(ds: Dataset, citations: Citation[]): DataCheck | null; // null when citations is empty
  ```
  Rules (spec §7, owner): "mentioned" = present in citations, answer text never parsed. Market-list rule: two or more distinct cited markets, all non-on-track at the latest month → `notMentioned` = `nonOnTrackMarkets(latest)` minus cited. Region rule: per cited region, its non-on-track markets not cited. Reason: non-on-track market with attainment ≥ 100 → `growth` (Spain: −4.6), else `attainment`.
