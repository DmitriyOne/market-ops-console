# Plan 8 · E2E: Playwright happy path, browser history, phone and axe, in CI (0.10.0)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (owner's usual flow: build → owner check → review → owner check). Steps use `- [ ]`.

**Status:** draft, waiting for the owner's approval.

**Goal.** The brief's "at least one E2E happy path", plus what jsdom cannot
check: real browser history (Back/Forward), the phone layout, and a rendered
accessibility scan the README can point to. Run on every PR into `develop`.

**Architecture.** Playwright Test in `e2e/` (outside `src`, no FSD), one
config for two targets: with `BASE_URL` set it tests that URL (a Vercel
preview, next release); without it, it builds and starts the app itself
(`next build` + `next start` on port 3100, the Next 16 guide's advice to
test a production build). Two projects: desktop Chromium and a phone
(Pixel 7 emulation, still Chromium). Locators by role and name only.
`@axe-core/playwright` for the accessibility scans.

**Tech stack.** New dev dependencies: `@playwright/test` ~1.63 (1.64.1 came
out on 2026-11-05; take the previous minor), `@axe-core/playwright` ~4.14,
`eslint-plugin-playwright` ~2.12. Existing: Next 16, the mock routes, the
GitHub Actions `pr-develop.yml` job.

**Spec:** §12 (testing), §6 (URL state, Back/Forward), §11 (accessibility).
ADR 0007 (CI), 0008 (testing scope). Backlog items marked "E2E".

**Sources checked (2026-11-05):** Next 16.2 guide "Testing: Playwright"
(build + start, `webServer`); Playwright docs: `webServer` with
`reuseExistingServer`, accessibility testing with `@axe-core/playwright`,
aria snapshots; Vercel KB "GitHub Actions with Vercel" (`deployment_status`
with `target_url`, protection bypass / Trusted Sources) for the next release.

## Owner decisions (2026-11-05)

1. **Where:** in CI on PRs into `develop` (option B), config ready for a
   Vercel preview run once the app is deployed (option C, next release).
2. **Scenarios:** the brief's happy path; Back/Forward in a real browser;
   the phone + axe scans. Not a separate alerts-on-the-real-API scenario.

## My calls (open to correction)

- Port **3100** for the E2E server, so the owner's dev server on :3000 is
  never reused or killed; `reuseExistingServer` only when not in CI.
- Mock delays through env for the E2E server: `MOCK_TOKEN_DELAY_MS=5`
  (an answer still streams, in a fraction of a second),
  `MOCK_ALERTS_DELAY_MS=400` (not in a scenario now; kept short if one is
  added).
- No `data-testid`: if a control cannot be found by role and name, that is
  an accessibility bug to fix in the app.
- No fixed waits (`waitForTimeout`): web-first assertions only.
- Locale: tests use the default `/dashboard` (en-GB) and one `/de-DE/`
  check of number formatting in the happy path; a new browser context per
  test, so no locale cookie or chat history leaks between tests.
- CI: `trace: 'on-first-retry'`, `retries: 1` in CI only, `forbidOnly` in
  CI, HTML report uploaded as an artifact only when a test fails.
- Not doing: visual regression, whole-page aria snapshots, WebKit/Firefox
  (ADR 0008 skips a cross-browser matrix; minutes).
- axe findings: real problems are fixed in the app in this release; a
  finding I think is wrong goes to the owner, never a silently disabled
  rule (an exclusion, if the owner agrees, is written in ADR 0008).

## Global constraints

- Branch `feature/0.10.0/e2e` from local `release/0.10.0` (= `develop`
  b811d28, after PR #26). Never push, merge or commit to `release/*`,
  `develop`, `master`.
- Skills: `next-best-practices`, `javascript-testing-patterns`,
  `accessibility`, `github-actions-efficiency` (before touching the
  workflow), TDD where it applies.
- Never relax ESLint/Steiger/TS rules; no `as` casts; app fixes keep the UI
  rules (no string literals, tokens, next-intl formats).
- Before each commit: `pnpm format && pnpm lint && pnpm typecheck && pnpm test`
  (+ `pnpm e2e` once it exists).
- The owner's dev server runs on :3000; never `next dev`.

## Review focus

1. Flaky timing: the stream, the map's first render (lazy topology), the
   sheet animation; every wait must be an assertion on what the user sees.
2. Port 3100 taken, or a stale `.next` from another branch: the run must
   fail clearly, not test old code.
3. CI minutes: the job stays one job, Chromium only, browsers cached by
   the Playwright version; the run must stay near +2 min.
4. The phone project must really be a phone (touch, viewport): the tab bar
   shows, the desktop sheet does not.
5. A `BASE_URL` run (preview) must not try to start a server or need the
   repo's env.
