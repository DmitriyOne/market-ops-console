**Status:** approved by the owner (2026-11-05); built on `feature/0.10.0/e2e` (tasks 1–6), waiting for the owner check, then the independent review.

**Goal.** The brief's "at least one E2E happy path", plus what jsdom cannot

`@axe-core/playwright` for the accessibility scans.

**Tech stack.** New dev dependencies: `@playwright/test` ~1.63 (1.64.1 came
out on 2026-11-05; take the previous minor), `@axe-core/playwright` ~4.14,
`eslint-plugin-playwright` ~2.12. Existing: Next 16, the mock routes, the
GitHub Actions `pr-develop.yml` job.

## Running it locally (owner, 2026-11-05: must work on his machine first)

The local run is the default; CI and the preview run reuse it.

- Once per machine: `pnpm exec playwright install chromium`.
- `pnpm e2e`: builds the app, starts it on :3100, runs both projects, stops
  the server. The owner's `pnpm dev` on :3000 can keep running (Next 16
  keeps the dev build apart from `next build`'s output; checked in task 1).
- `pnpm e2e:ui`: Playwright's UI mode (pick a test, watch it, time-travel
  through its steps).
- `pnpm e2e --project=desktop` / `--project=phone`, `pnpm e2e --headed`
  (a visible browser), `pnpm exec playwright show-report` (last HTML
  report), `pnpm exec playwright show-trace test-results/…/trace.zip`.
- Faster reruns: with a server already on :3100 (`pnpm build && pnpm start --port 3100`
  in another terminal) the run reuses it and skips the build.
- Every task is done only when `pnpm e2e` passes locally; the README's
  Quick start lists these commands.

## My calls (open to correction)

- Port **3100** for the E2E server, so the owner's dev server on :3000 is
  never reused or killed; `reuseExistingServer` only when not in CI.
- Mock delays through env for the E2E server: `MOCK_TOKEN_DELAY_MS=20`
  (was 5; raised so Stop can land mid-answer),
  `MOCK_ALERTS_DELAY_MS=400` (not in a scenario now; kept short if one is
  added).
- No `data-testid`: if a control cannot be found by role and name, that is
  an accessibility bug to fix in the app.
- No fixed waits (`waitForTimeout`): web-first assertions only.
- Locale: tests use the default `/dashboard` (en-GB) and one `/de-DE/`
  check of number formatting in the happy path; a new browser context per
  test, so no locale cookie or chat history leaks between tests.
- CI: `trace: 'on-first-retry'`, `retries: 1` in CI only, `forbidOnly` in
  CI, HTML report uploaded as an artifact only when a test fails.
- Not doing: visual regression, whole-page aria snapshots, WebKit/Firefox
  (ADR 0008 skips a cross-browser matrix; minutes).
- axe findings: real problems are fixed in the app in this release; a
  finding I think is wrong goes to the owner, never a silently disabled
  rule (an exclusion, if the owner agrees, is written in ADR 0008).

## Review focus

1. Flaky timing: the stream, the map's first render (lazy topology), the
   sheet animation; every wait must be an assertion on what the user sees.
2. Port 3100 taken, or a stale `.next` from another branch: the run must
   fail clearly, not test old code.
3. CI minutes: the job stays one job, Chromium only, browsers cached by
   the Playwright version; the run must stay near +2 min.
4. The phone project must really be a phone (touch, viewport): the tab bar
   shows, the desktop sheet does not.
5. A `BASE_URL` run (preview) must not try to start a server or need the
   repo's env.

## Built differently from the plan

- **Playwright 1.64.1**, not 1.63: the "came out today" date was an alpha's; 1.64.1 is from 2026-10-14.
- **Projects by file** (`testMatch` / `testIgnore`), not `test.skip`: desktop runs every spec but the phone's; the phone runs its own, the smoke test and the axe scans.
- **Streaming is checked by counting text updates** in the assistant while the answer comes (more than 20), not by catching "writing…", which a 5 ms token delay makes too short to see reliably.
- **Keyboard on the map** (Shift+Enter) for the selection test: Europe is small on the world map and a mouse click waited for it.
- **axe found WCAG 2.5.3 (label in name)** on heat-map cells (109) and status tiles (58): names changed with the owner's choice of wording (`cellRounded`, tile message), plus a space between the tile's two visible parts.
- **The axe fixture waits for finite animations** (a sheet fading in read as low contrast once in ~140 runs).
- **Two picks within nuqs's URL throttle share one history entry**; the test waits for the first pick in the URL (a person does not pick twice within 50 ms).
- **The develop job limit is 14 min**, not 12: the unit tests alone take ~5 min on the runner (backlog).
- The `use` argument of the Playwright fixture is named `provide`: React's hook rule mistook it for a hook; the rule stays on.

## Added after the build (owner, 2026-11-05)

- **More E2E**: alerts on the real cookie route (save, reload, rollback, Retry, Show); the assistant's error with Try again and its "can't answer"; offline and a failing alerts API. A test for the dataset API failing was dropped: the dataset is read at build time into the static page (`HydrationBoundary`, `staleTime: Infinity`), so the browser never fetches it; the unit test keeps that path.
- **A bug the alerts E2E found**: toast buttons could not be clicked over the modal alerts sheet (`pointer-events: none` on `<body>` inherited by the toasts). Toasts take pointer events back; a press on one does not close the sheet (`SheetContent` ignores interactions inside the toaster). Keyboard access to a toast over the sheet stays open (backlog).
- **Two more E2E** (owner asked for the flows a reviewer would not click by hand): Stop mid-answer (token delay 5 → 20 ms on the E2E server, so the long answer takes ~3.5 s), and a shared link opened in a fresh browser plus the mode switch undone by Back. The happy path also checks the authoritative "What the data shows" block next to the AI answer.
- **Faster unit tests**: the setup file imports only the MSW server, logic tests run in `node` (Vitest projects); 72 s → 58 s with two workers.
