# Plan 7 · Alerts: threshold rules with optimistic save (0.9.0)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (owner's usual flow: build → owner check → review → owner check). Steps use `- [ ]`.

**Status:** approved by the owner (2026-11-05); building on `feature/0.9.0/alerts`.

**Goal.** The brief's form requirement: "at least one non-trivial,
schema-validated form … an alert / threshold configurator … save it with
an optimistic update and roll back on failure". Users write rules such as
"attainment below 95 %"; the markets a rule flags get a bell in the
markets table, the map's tooltip and table, and Top risks; the header
counts them.

**Architecture.** One zod schema for a rule in `shared/api/alerts`, used by
the mock route and the form, so client and server validate the same way.
`app/api/v1/alerts` keeps the rules in a cookie (GET/POST/PATCH/DELETE,
~600 ms). `entities/alert-rule` holds the query and `evaluateRules`
(stored latest KPIs). `features/configure-alerts` holds the form
(react-hook-form + zod resolver), the list and the mutations (TanStack
optimistic update, rollback, toast with Retry). The panel opens from
`tab=alerts`: a right sheet on desktop, a tab on the phone.

**Tech stack.** New: `react-hook-form`, `@hookform/resolvers` (ADR 0002
already lists them "installed with alerts"); shadcn `input`, `label`,
`select`, `switch`, `checkbox`, `alert-dialog`. Existing: TanStack Query,
zod 4, sonner, nuqs, next-intl, Vitest + RTL + MSW.

**Spec:** `docs/specs/2026-11-03-market-ops-console-design.md` §6 (`tab`),
§8 (Top risks), §9, §10, §11a, §12. ADR 0002, 0006, 0012, 0013, 0015.

| Rule | Flags |

Monthly market revenue is 0.76–3.78 M$.

## Owner decisions (2026-11-05)

1. **First visit shows two example rules** (no cookie yet): "Attainment
   below 95 %" (critical, DE GB IT) and "Share below 10 %" (warning, US DE
   AU), so the bells and the count show at once; they can be edited or
   deleted like any rule.
2. **Rules always judge the latest month** (like status): an alert is
   "now". The preview and the bells say "May 2026"; the dashboard's period
   does not change them.
3. **Where the bell shows:** the markets table and Top risks (Top risks
   adds flagged markets even when they are on track), plus **a line in the
   map's tooltip and a column in the map's table view** (no icon drawn on
   the map). The header counts flagged markets. Not on the tiles or the
   heat map. Spec §9 changes from "map and table" to this.
4. **`tab=alerts` works on desktop too**: on the phone it is the Alerts
   tab, on desktop the same link opens the right sheet. Back closes it.
5. **Scope "markets": a list in the form** (13 markets with checkboxes,
   grouped by region); a new rule starts with the dashboard's current
   selection (`markets`) ticked. The rule keeps its own list.
6. **Delete asks first** ("Delete rule …?"), then removes optimistically
   and restores on failure.
7. **Desktop sheet built from the tokens** and the phone board, no new
   design artifact; the owner checks it on the build.

## My calls (open to correction)

- **Rule:** `{ id, name, metric: growth|attainment|share|revenue,
  operator: below|above, threshold, scope: {kind:'portfolio'} |
  {kind:'region', regionId} | {kind:'markets', marketIds[]}, severity:
  warning|critical, enabled }`. Validation as spec §9: threshold ranges
  (growth −100…100, attainment 0…200, share 0…100, revenue ≥ 0), ≥ 1
  market for scope "markets", name 1–60 characters and unique (ignoring
  case and spaces at the ends), at most 10 rules. "Below" is strict
  (`<`), "above" is strict (`>`), on the value as stored (one decimal).
- **Revenue threshold is typed in millions of USD** (`1.5` = $1.5M; the
  field shows "M$" next to it), because monthly revenue is 0.8–3.8 M$.
  Stored in USD.
- **Market level only**: rules read `markets[].kpis` (source of truth for
  the latest month, spec §5); an open product does not change them.
- **Bell = lucide icon, not the emoji**: `BellIcon` for warning,
  `BellRingIcon` for critical, with the rule names as text (tooltip / sr
  text), so the severity is not colour only. A market flagged by several
  rules shows one bell at its highest severity and lists every rule.
- **Top risks:** flagged on-track markets go after the at-risk ones,
  critical first; a flagged at-risk or off-track market keeps its place
  and gets the bell. Off the latest 1-month view Top risks already shows
  the "latest month only" notice; flagged markets wait for that view too,
  so the card never mixes two months.
- **Header:** a bell button with the number of flagged markets (enabled
  rules only) next to the mode switch; on the phone the Alerts tab carries
  the same number. No number until the rules load; nothing breaks if they
  fail (the panel says so with Retry).
- **Panel:** the list (name, plain-language condition "Attainment below
  95 % · Europe", severity, an enabled switch, Edit, Delete) and a "New
  rule" button that opens the form in the same panel. The form shows a
  live preview: "Would flag 3 markets now (May 2026): Germany, United
  Kingdom, Italy" or "Would flag no markets now". The form is short:
  closing the sheet drops an unsaved draft (no "discard?" dialog).
- **Optimistic flow:** create shows the rule at once as "Saving…" (temp
  id), toggle and edit change it at once, delete removes it at once; on
  failure the cache goes back to the snapshot and a toast says "Couldn't
  save — restored previous state" with Retry. `cancelQueries` before each
  optimistic write; the query client then must not log TanStack's
  `CancelledError` (backlog item from the error-handling review, now
  real: fixed with a test).
- **"Simulate failure"**: a switch at the bottom of the panel, "Fail the
  next save (demo)"; the next mutation sends `x-simulate-failure: 1`, the
  route answers 503 `{ error: { code: 'simulated' } }`, the switch turns
  itself off. In memory only (a reload clears it).
- **Route:** cookie `mo-alerts` (httpOnly, SameSite=Lax, path
  `/api/v1/alerts`, 1 year), base64url JSON, read through the zod schema
  (a broken cookie counts as absent). Server checks the same rules and
  returns 400 `invalid`, 409 `duplicateName`, 409 `tooMany`, 404
  `notFound`; the client maps the codes to translated messages. Example
  names come from the messages of the locale the client sends
  (`?locale=`), so a Russian page gets Russian examples.
- **Phone:** the Alerts tab hides the header like the Assistant tab (rules
  do not use the period); `?tab=alerts` is marked before paint like
  `?tab=assistant` (ADR 0015).
- **Exports unchanged:** CSV/Excel hold data, not the user's rules.
- **Release:** `package.json` → `0.9.0`, CHANGELOG `0.9.0`; spec §6/§8/§9,
  ADR 0002/0006, DESIGN.md, README and CLAUDE.md updated to what is built.

## Review focus

1. Two quick saves in a row (create, then toggle before the first answer):
   the second rollback must not bring back a state from before the first.
2. Failure on delete or toggle restores exactly that rule, in its place.
3. A rule edited so it flags nothing: the bell disappears everywhere,
   the count drops, Top risks loses the on-track market.
4. Back/forward with the sheet open, and `tab=alerts` opened on a phone
   then the window widened (one panel, not two).
5. Number input in de-DE (comma) and an empty threshold: a translated
   message, never NaN in the preview.
