# 0007. Git flow and CI

**Context.** GitHub Free, private repo: 2,000 Actions minutes/month, each job rounded up to a minute; branch protection/rulesets unavailable (403). Owner does not want husky.

**Decision.**
- Flow: `feature/X.Y.Z/NAME` (or `fix/X.Y.Z/NAME`) → `release/X.Y.Z` → `develop` → `master`. First release `0.1.0` (architecture/planning); submission is `1.0.0`.
- No direct commits to `release/*`, `develop` or `master`. Work happens on `feature/X.Y.Z/NAME` branched from `release/X.Y.Z`, so every branch shows its release (not `release/X.Y.Z/NAME`: git ref conflict, and it would pass the `release/*` CI check); release branches only receive merges from them.
- One job per check, in parallel (owner, 2026-11-05, 0.11.1): each check is its own line and log in the PR instead of one long log. Until 0.11.0 every workflow was one job, to spend the fewest minutes; each job now installs on its own (`.github/actions/setup`), so a run costs more minutes but is shorter to wait for.
- PR → `release/*`: Format, Lint, Types (pnpm cache), no tests. ~1 min to wait, ~4 billed (~2 as one job). Catches a broken feature before the release PR.
- PR → `develop`: Branch & version first: head must be `release/*` (else comment + auto-close), version check (`package.json` = top of `CHANGELOG.md` = branch number), no install. Then, after it, in parallel: Format, Lint, Types, Unit tests, and E2E, which builds the app (0.10.0, ADR 0008; Chromium only, browsers and the Next build cache cached, report on failure; the E2E step limited to 10 min, its job to 15). Measured as one job on the 0.10.0 PR into `develop` (2026-11-05): 5 min 58 s in all, the unit tests 2 min 50 s on the 2-core runner (4 min 39 s before 0.10.0 sped them up), the E2E step with the build 1 min 26 s, Chromium's first install 21 s (cached after). The 0.11.0 PR took 7 min 27 s as one job (8 billed; Chromium missed its cache). Expected after the split: ~4.5 min to wait (the unit tests' job), ~13 billed minutes a run instead of ~8 (each job pays ~30 s of setup and install and rounds up). Measured on the 0.11.1 PR (2026-11-05): 12 min 24 s to wait, ~20 billed, because Chromium missed its cache and took 9 min 39 s to download (cached after); without it E2E ~2.5 min, the unit tests' job 2 min 46 s, Format, Lint, Types under a minute each. A cancelled run now costs a minute per started job.
- PR → `master`: one job: head must be `develop` (else auto-close), version check. No install. ~15 s.
- No workflows on push. `concurrency` cancels superseded runs. Vercel builds previews on its own quota.

**Alternatives.** Full CI on every PR (burns minutes); one job per workflow (the fewest minutes, but every check in one log; used until 0.11.0); one workflow file per check (the branch and version gate repeated in each); husky hooks (rejected by owner); making the repo public (unlimited minutes + real branch protection) — possible later.

**Consequences.** Auto-close is the only enforcement; a red check does not block the Merge button (no required checks on this plan); the owner can still push directly to `master`/`develop`. A title or body edit starts a run whose jobs are all skipped; the PR may then list the checks as skipped rather than an earlier red (not yet seen; the same was true of the one job, now it is six lines).
