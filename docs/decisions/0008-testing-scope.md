# 0008. Testing scope

**Decision.**
- Unit (TDD): SSE parsing, zod schemas, selectors/aggregations, formatters, chat reducer.
- Component/integration (Vitest + Testing Library + MSW): chat streaming/stop/error/abstain/low-confidence, citations, drill-down updating URL, alert form validation and optimistic rollback, chart table alternatives.
- E2E (Playwright, `e2e/`, 0.10.0): the happy path (map → Germany → URL → the assistant's answer streams → a source opens that market and month), Back/Forward in a real browser, the phone tab bar, alerts on the real cookie route (optimistic save, reload, rollback, Retry), the assistant's error, "can't answer" and Stop mid-answer (the E2E server streams a word every 20 ms so Stop lands mid-answer), a shared link in a fresh browser and the mode switch with Back, Excel/CSV export as real downloads, offline and a failing alerts API (the dataset ships inside the static page, so a dataset failure cannot happen at run time and is covered by unit tests only), and axe scans (WCAG 2.1 A/AA) of the main views on desktop and phone. Since 0.11.0 also what axe can't catch: the map by keyboard when zoomed in (a market off the edge comes into view, ringed on top) and by a tap (no keyboard ring), Retry by keyboard inside the modal alerts sheet, focus kept across the offline notice. Since 0.12.0 the currency picker (amounts in € and £, kept after a reload, the phone settings row). Since 0.13.0 `robots.txt`, the icons and the preview images (the default locale's with no redirect), the page title, description and preview tags in the page language, and the localised 404 with status 404 and an axe scan; the 500 pages are unit-tested (no route throws). Since 0.14.0 Sentry runs on in the E2E build with a DSN on a local port nothing listens on; a fixture catches every browser envelope at the tunnel and fails a test if the browser calls sentry.io; `e2e/sentry.spec.ts` checks the real SDK's events (a failing API reported with the screen's tags and no personal data, the demo save failure and a server-reported 5xx kept as breadcrumbs, the question text never sent) and that the test page and its API are 404s. Unit level adds a real server SDK with our options (`sentry.server.test.ts`: no IP, cookies or headers from a request error) and `next.config.test.ts` (no experimental flag). Locators by role and name only, no fixed waits. Two projects, both Chromium: desktop 1440×900 and Pixel 7.
- Where: locally with `pnpm e2e` (builds the app and starts it on :3100, apart from a dev server on :3000) and on every PR into `develop` (owner, 2026-11-05; ADR 0007). With `BASE_URL` the same suite tests a deployed preview (planned with the deploy).
- axe findings are fixed in the app; an exclusion would be written here (none so far). axe catches a part of the problems only: keyboard and screen-reader checks stay manual.

**Skipped.** Visual regression (fonts and OS make screenshots flaky), whole-page aria snapshots (break on any copy change), Storybook, a cross-browser matrix (WebKit/Firefox: CI minutes).
